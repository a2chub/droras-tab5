# ヒートボード（Tab5 アプリ）

ドローンレースのヒート表を表示し、[droras](https://github.com/a2chub/droras) サーバーの
操作パネルとしても使える M5Stack Tab5 用アプリ。<https://info.japandroneleague.com/> および
droras の操作画面と同等の表示・操作を Tab5 単体で行う。

## 画面

### ボード画面

- 4行表示: **1つ前 / 現在 / 次 / 次の次** のヒート（リストの端では循環する）。
- 現在のヒートは緑の帯で強調し、選手名は 48px。前後のヒートは 36px。列幅に収まらない名前は自動で縮小する。
- 列は映像チャンネル順（R2 / F1 / R4 / R5）。名前が空の枠は `-` と表示する。
- 上部のステータスバーに取得元を表示する（緑: RPi に接続中 / 黄: Firestore から取得中 / 赤: 取得できない）。
- ボタン（RPi に接続中のみ有効。未接続時はグレーになり、押すと低い音が鳴る）:
  - **スタート**: droras にスタートシーケンスを要求し、150 秒のタイマーを開始。満了で次のヒートへ進む。
    タイマー中は「ストップ」になり、押すとこの端末のタイマーだけを止める（droras 側のシーケンスは止まらない）。
  - **前のヒート / 次のヒート**: droras の現在ヒートを変更する。表示は droras からの通知で更新されるため、
    他の端末やブラウザの操作画面とも同期する。
- ボタンを押すとタッチ音が鳴る（受け付けた操作はドミソの和音、受け付けられない操作は低い2音）。
- 前/次のヒートは、サーバーの応答を待たずに押した時点で表示を切り替える。自分が送った変更に対する
  サーバーからの通知は数えておき、連打時に古い通知で表示が巻き戻らないようにしている。
- 画面は裏バッファに描いてから一括で転送するので、書き換わる途中の状態は見えない。
- 表示中のヒートの次と前の表は、空き時間に別の裏バッファへあらかじめ描いておく。隣のヒートへの
  切り替えは転送だけで済み、約50〜60ms（離れたヒートへ飛ぶ場合はその場で描くので約100ms）。
  所要時間はシリアルログに `heat N: drawn in X ms, copied to the panel in Y ms` として出る。

### 設定画面（右上の「設定」）

| タブ | 内容 |
|---|---|
| Wi-Fi | `src/app_secrets.h` に登録した最大4件のプリセットをラベル付きボタンで表示し、タップで切り替える。接続状態と Tab5 の IP アドレスを表示 |
| サーバー | RPi（droras）の IP アドレスをテンキーで入力（`192.168.1.20` または `192.168.1.20:8000`。ポート省略時は 8000）。空欄で保存すると RPi を使わない。「選手リストを再取得」ボタン |
| 音量・明るさ | タッチ音の音量（0〜10）と画面の明るさ（1〜10）。－/＋ またはバーをタップ |
| 画面の向き | 「自動（センサー）」「通常の向き」「上下反転」から選ぶ（既定は自動）。現在の表示の向きと加速度センサーの判定を表示 |

Wi-Fi の選択、サーバーアドレス、音量、明るさ、画面の向きは本体に保存され、電源を切っても保持される。

### 画面の向き（上下反転）

- 対応するのは横向きの 2 通り（通常 / 180° 回転）のみ。縦向きのレイアウトは無い。
- 自動では内蔵の加速度センサー（BMI270）を 50ms ごとに読む。画面の縦方向の重力成分が
  ±0.5g（平置きから約30°起こした状態）を超え、その状態が 0.6 秒続いたら向きを切り替える。
  平らに置いている間や、タップなどによる一瞬の揺れでは切り替わらない。起動直後だけは最初の判定を即座に採用する。
- 判定ロジックは `components/heatboard_core` の `orientation`（単体テストあり）。
- 反転は裏バッファを逆順に並べ替え、座標の対応とディスプレイの回転（M5GFX の rotation を +2）を
  切り替えて行う。描き直しは不要で、タッチ座標・画面キャプチャも表示と同じ座標系のまま。

## データの取得元

| データ | 取得元 | 備考 |
|---|---|---|
| 選手リスト | GAS エンドポイント（CSV: `JDLid,name,class,heat`） | 起動時と「選手リストを再取得」で取得。失敗時は 2〜30 秒間隔で自動再試行 |
| 現在のヒート（優先） | RPi の droras（Socket.IO、`current_heat` イベント） | 即時反映。操作ボタンもこの接続を使う |
| 現在のヒート（代替） | Firestore `race/current` の `heat`（REST、認証不要） | RPi に繋がらない間だけ 3 秒間隔でポーリング。表示専用 |

エンドポイントの URL と間隔は `src/app_config.h` にある。

Firestore の無料枠は 1 日 5 万読み取りで、公開サイトと共有している。3 秒間隔なら 1 台が丸 1 日
代替動作しても約 2.9 万回に収まるが、**複数台を長時間 Firestore だけで動かす場合は間隔を延ばすこと**。

## 構成

```
src/
  main.cpp             画面遷移とメインループ（UI は全てメインタスク）
  board_screen.*       ボード画面
  settings_screen.*    設定画面（4タブ）
  ui_common.*          色・ボタン・タッチ音・音量/明るさ・上下反転
  screen_orientation.* 加速度センサーによる画面の向きの自動切り替え
  canvas.*             画面全体の裏バッファ（塗り・角丸・文字の合成・パネルへの転送）
  text_renderer.*      FreeType による文字描画（グリフキャッシュ付き）
  network_task.*       通信全体を担うバックグラウンドタスク
  wifi_station.*       Wi-Fi（ESP32-C6 経由）とプリセット切り替え
  droras_client.*      RPi の droras との Socket.IO 接続
  heat_sources.*       GAS の選手リスト取得、Firestore の現在ヒート取得
  http_client.*        HTTPS GET（リダイレクト追従、接続の再利用）
  app_state.*          通信タスクと UI の間で共有する状態
  settings_store.*     NVS への設定保存
  debug_console.*      USB シリアルからの操作・画面ダンプ
components/heatboard_core/   ハードウェア非依存のロジック（PC 上で単体テスト可能）
  heat_list            選手リスト CSV の解析
  heat_window          表示する4ヒートと前後のヒート番号の算出
  socketio_codec       Engine.IO v4 / Socket.IO v5 のフレーム処理
  server_address       IP アドレス入力の検証
  orientation          加速度センサーの値から画面の向きを判定（揺れ・平置きの扱い）
test/test_heatboard_core/    上記の単体テスト（`pio test -e native`）
tools/screenshot.py          画面キャプチャ・リモート操作
```

## 既知の制約

- 選手リストは GAS からのみ取得する。インターネットに出られない会場 LAN では、RPi に繋がっても選手名は表示できない。
- IPAex ゴシックに無い文字（例: 𠮷 U+20BB7）は表示されない。
- droras 操作画面の「ヒートリスト再読み込み / 再ダウンロード / ログアップロード」に相当する
  RPi 側の操作は実装していない（設定画面の「選手リストを再取得」は Tab5 自身のリストを取り直すだけ）。
- RPi のアドレスは IPv4 の数値のみ（`jdl-pi.local` のようなホスト名は入力できない）。
- アプリがフラッシュのほぼ全域を使うため OTA 更新はできない。更新は USB から行う。
- 無線モジュール（ESP32-C6）側のファームウェアは出荷時のままで、ホスト側ライブラリより古い（起動時に警告が出る）。
