# ヒートボード（Tab5 アプリ）

ドローンレースのヒート表を表示し、[droras](https://github.com/a2chub/droras) サーバーの
操作パネルとしても使える M5Stack Tab5 用アプリ。<https://info.japandroneleague.com/> および
droras の操作画面と同等の表示・操作を Tab5 単体で行う。

## 画面

### ボード画面

- 4行表示: **1つ前 / 現在 / 次 / 次の次** のヒート（リストの端では循環する）。
- 現在のヒートは緑の帯で強調し、選手名は 48px。前後のヒートは 36px。列幅に収まらない名前は自動で縮小する。
- 列は映像チャンネル順（R2 / F1 / R4 / R5）。名前が空の枠は `-` と表示する。
- 上部のステータスバーに取得元を表示する（緑: RPi に接続中 / 黄: Firestore から取得中 / 赤: 取得できない）。
- 上部に Wi-Fi の電波強度とサーバーの応答状態をアイコン表示する。設定画面でも同じ位置に表示する。
- ボタン（RPi に接続中のみ有効。未接続時はグレーになり、押すと低い音が鳴る）:
  - **スタート**: droras にスタートシーケンスを要求し、150 秒のタイマーを開始。満了で次のヒートへ進む。
    タイマー中は「ストップ」になり、押すとこの端末のタイマーだけを止める（droras 側のシーケンスは止まらない）。
  - **前のヒート / 次のヒート**: droras の現在ヒートを変更する。表示は droras からの通知で更新されるため、
    他の端末やブラウザの操作画面とも同期する。
- ボタンを押すとタッチ音が鳴る（受け付けた操作はドミソの和音、受け付けられない操作は低い2音）。
- 前/次のヒートは、サーバーの応答を待たずに押した時点で表示を切り替える。自分が送った変更に対する
  サーバーからの通知は数えておき、連打時に古い通知で表示が巻き戻らないようにしている。
- 画面は裏バッファに描いてから一括で転送するので、書き換わる途中の状態は見えない。
- 表示中のヒートの次と前の表は、空き時間に別の裏バッファへあらかじめ描いておく。隣のヒートへの
  切り替えは転送だけで済み、約50〜60ms（離れたヒートへ飛ぶ場合はその場で描くので約100ms）。
  所要時間はシリアルログに `heat N: drawn in X ms, copied to the panel in Y ms` として出る。

### 設定画面（右上の「設定」）

| タブ | 内容 |
|---|---|
| Wi-Fi | 最大4枠の SSID・パスワードを本体で登録／編集。「未登録」の枠または「編集」で入力し、「保存して接続」で反映。登録済みの Wi-Fi 名をタップして接続先を切り替える。接続状態・IP アドレス・電波強度（dBm）を表示 |
| サーバー | RPi（droras）の IP アドレスをテンキーで入力（`192.168.1.20` または `192.168.1.20:8000`。ポート省略時は 8000）。空欄で保存すると RPi を使わない。生存確認の状態を表示し、「選手リストを再取得」ボタンで再取得 |
| 音量・明るさ | タッチ音の音量（0〜10）と画面の明るさ（1〜10）。－/＋ またはバーをタップ |
| 画面の向き | 「自動（センサー）」「通常の向き」「上下反転」から選ぶ（既定は自動）。現在の表示の向きと加速度センサーの判定を表示 |
| ジェスチャー | カメラに手の形を見せての操作を「使う／使わない」（既定は使わない）。確定までの時間（0.3〜2.0 秒）、前のヒート／次のヒート／スタート・ストップに割り当てる手の形（◀ ▶ で切り替え）。カメラがいま何を認識しているかを表示 |
| カメラ | 認識が見ている映像（320x180 を 3 倍、鏡像）をライブ表示。検出した手に枠（緑＝形を認識、黄＝形が不明）、判定結果と確信度、割り当てられた操作、確定までのバー。このタブを開いている間は「使わない」設定でも認識だけ動く（操作は発火しない） |

Wi-Fi の SSID・パスワードと接続先の選択、サーバーアドレス、音量、明るさ、画面の向き、ジェスチャーの設定は
本体に保存され、電源を切っても保持される。

### Wi-Fi 電波強度とサーバーの生存確認

ヘッダーに4本の電波バーとサーバー筐体のアイコンを表示し、それぞれ「Wi-Fi」「サーバー」のラベルを付ける。

| 表示 | Wi-Fi | サーバー |
|---|---|---|
| 灰色 `−` | 未設定 | 未設定 |
| 黄色 `…` | 接続中 | 接続確認中・Wi-Fi 接続待ち |
| 緑 `○` | 接続済み | droras の Socket.IO 接続が成立し、定期通信が期限内に届いている |
| 赤 `×` | 接続失敗 | 通信断・応答期限切れ。再接続が成立するまで表示 |

電波強度（RSSI）は接続中のアクセスポイントから約2秒ごとに取得する。バーの基準は次のとおり。

| RSSI | バー | 設定画面の目安 |
|---|---|---|
| −55 dBm 以上 | 4本 | 強い |
| −65 dBm 以上、−55 dBm 未満 | 3本 | 良好 |
| −75 dBm 以上、−65 dBm 未満 | 2本 | 弱め |
| −75 dBm 未満 | 1本 | 弱い |

接続済みでも測定できないときは `?` を表示する。Wi-Fi が切断されたら以前の測定値とサーバーの正常表示を解除する。
「設定 → Wi-Fi」には `電波: -XX dBm（良好）` のように実測値も表示する。

サーバーの確認には、既存の Socket.IO 接続で届く Engine.IO の定期通信（heartbeat）を使う。
接続開始時の handshake と、その後の Socket.IO namespace 接続はそれぞれ10秒以内に成立する必要がある。
接続後は、handshake または直近の Engine.IO ping から `pingInterval + pingTimeout` が経過すると応答停止とする。
この期限にはサーバーから通知される正の整数値を使い、合計120秒を超える値は受け付けない。
失敗後は3秒待って再試行する。Wi-Fi が切れた場合も接続済み状態を解除する。
新しい HTTP ヘルスチェック用 API は使わず、droras との通信が応答しているかを監視する。

「設定 → サーバー」の「生存確認」に、直近の応答あり／応答待ち／応答がありません／Wi-Fi接続待ち／未設定を表示する。
実機で未設定・Wi-Fi接続待ちのヘッダー表示と、設定各タブ・入力画面の表示を確認済み。
電波強度の実測とサーバー通信断・復旧の確認は未実施。

### Wi-Fi の登録と編集

- 「設定 → Wi-Fi」で未登録の枠、または各枠の「編集」を押して入力画面を開く。
  SSID／パスワード欄をタップし、英数字・記号のタッチキーボードで入力する。
- SSID は空欄不可・最大32バイト。前後の空白はそのまま保持する。制御文字は使えない。
- パスワードは8〜63文字のASCII英数字・記号・空白、または64桁の16進PSK。
  暗号化なしのネットワークは空欄にする。入力は伏せ字で、「表示／隠す」で確認できる。
- 「保存して接続」で本体に保存し、接続を要求する。同じ枠を編集中でも新しい内容で再接続する。
  接続に失敗した場合は再編集できる。「キャンセル」は保存や接続切り替えを行わずに戻る。
- 入力値が不正な場合や保存に失敗した場合は編集画面に残り、入力内容を修正・再保存できる。
- `src/app_secrets.h` は任意の初期値。ファイルなしでもビルドでき、本体に保存した各枠の値を優先する。
  保存値がない枠は従来のソース側設定を読み込む。

端末上の Wi-Fi 編集機能は、実機で起動・入力画面・入力チェック・キャンセルを確認済み。
接続成功と、保存後の再起動による設定保持は未確認。
確認項目は [開発環境セットアップ](development-setup.md#wi-fi-編集機能の実機確認項目) を参照。

### ジェスチャー操作（カメラ）

- 内蔵カメラ（SC2356、MIPI-CSI）の映像を ESP-DL の 2 つのモデル（手の検出 → 手の形の分類）に通し、
  毎秒 7〜10 回判定する。認識できる形は 指1本／2本／3本／4本／パー／グッド（親指上）／OK／電話／親指下。
- 同じ形が「確定までの時間」の間見え続けると、割り当てたボタンを押したのと同じ動作になる。手を上げている間は
  1 回しか発火せず、手を下げる（0.4 秒以上見えなくなる）とまた受け付ける。発火後 1 秒は何も受け付けない。
  判定ロジックは `components/heatboard_core` の `gesture_control`（単体テストあり）。
- 発火までの間、ボード画面の上部に「手: ピース → 次のヒート」と進み具合のバーが出る。設定画面を開いている間は発火しない。
- **認識できる条件**: 手がカメラから 0.5〜1.5m、手のひらをカメラに向け、**手に光が当たっている**こと。
  逆光（背後に窓やライト）や暗い部屋では認識率が大きく落ちる。検出器は「画面の大半を占める大きな手」を
  検出できないため、近すぎる手も認識されない（解析画像は 1280x720 を 1/4 に縮小したもの）。
- 露出とゲインは本体側で自動調整する（画面中央部の明るさが一定になるよう、露光時間→ゲインの順に使う）。
  ホワイトバランスはフレーム全体のグレーワールド、ISP のノイズ除去とガンマ補正も有効。
- 消費電力と発熱は増える。ジェスチャーを「使わない」にしてもカメラは動いたままで、推論だけ止まる。

### 画面の向き（上下反転）

- 対応するのは横向きの 2 通り（通常 / 180° 回転）のみ。縦向きのレイアウトは無い。
- 自動では内蔵の加速度センサー（BMI270）を 50ms ごとに読む。画面の縦方向の重力成分が
  ±0.5g（平置きから約30°起こした状態）を超え、その状態が 0.6 秒続いたら向きを切り替える。
  平らに置いている間や、タップなどによる一瞬の揺れでは切り替わらない。起動直後だけは最初の判定を即座に採用する。
- 判定ロジックは `components/heatboard_core` の `orientation`（単体テストあり）。
- 反転は裏バッファを逆順に並べ替え、座標の対応とディスプレイの回転（M5GFX の rotation を +2）を
  切り替えて行う。描き直しは不要で、タッチ座標・画面キャプチャも表示と同じ座標系のまま。

## データの取得元

| データ | 取得元 | 備考 |
|---|---|---|
| 選手リスト | GAS エンドポイント（CSV: `JDLid,name,class,heat`） | 起動時と「選手リストを再取得」で取得。失敗時は 2〜30 秒間隔で自動再試行 |
| 選手リスト（RPi 経由） | droras の `heat_list` イベント（接続時と RPi 側の再読み込み時に届く） | 届いたら常に採用する。インターネットに出られない会場でも RPi に繋がれば選手名が出る |
| 現在のヒート（優先） | RPi の droras（Socket.IO、`current_heat` イベント） | 即時反映。操作ボタンもこの接続を使う |
| 現在のヒート（代替） | Firestore `race/current` の `heat`（REST、認証不要） | RPi に繋がらない間だけ 3 秒間隔でポーリング。表示専用。Firestore 自体に届かないときは間隔を 2 倍ずつ最大 60 秒まで延ばす |

エンドポイントの URL と間隔は `src/app_config.h` にある。

Firestore の無料枠は 1 日 5 万読み取りで、公開サイトと共有している。3 秒間隔なら 1 台が丸 1 日
代替動作しても約 2.9 万回に収まるが、**複数台を長時間 Firestore だけで動かす場合は間隔を延ばすこと**。

## 既知の制約

- 選手リストは GAS か RPi から取得する。インターネットに出られず RPi にも繋がらない状態では選手名は表示できない。
- IPAex ゴシックに無い文字（例: 𠮷 U+20BB7）は表示されない。
- droras 操作画面の「ヒートリスト再読み込み / 再ダウンロード / ログアップロード」に相当する
  RPi 側の操作は実装していない（設定画面の「選手リストを再取得」は Tab5 自身のリストを取り直すだけ）。
- RPi のアドレスは IPv4 の数値のみ（`jdl-pi.local` のようなホスト名は入力できない）。
- Wi-Fi のタッチキーボードはASCII英数字・記号のみで、日本語の SSID は新規入力できない。
  ソース側の初期値に含まれる日本語の SSID は保持できる。周囲のアクセスポイントを検索する機能はない。
- アプリがフラッシュのほぼ全域を使うため OTA 更新はできない。更新は USB から行う。
- 無線モジュール（ESP32-C6）側のファームウェアは出荷時のままで、ホスト側ライブラリより古い（起動時に警告が出る）。
